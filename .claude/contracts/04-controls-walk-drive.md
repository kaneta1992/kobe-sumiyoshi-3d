# 契約04: 操作系 — 徒歩・車両運転・スマホタッチ対応（確定版）

ダイヤル: Opus向けゴール委譲

## 目的

- 要求: 三人称の徒歩移動と車両運転を実装し、PC（WASD+マウス）とスマホ（タッチ）の両方で操作できるようにする。
- ゴール: 「実在の町を歩き回ったり車で運転できる」というアプリの中核体験。後続のマルチプレイはこの移動状態を同期する。
- 成功条件: ブラウザで住吉山手の坂道を歩いて上り下りでき、車に乗って運転でき、スマホ（タッチエミュレーション）でも同等の操作ができる。すり抜け・落下・物理爆発がない。

## コンテキスト

- 既存実装: C:\Users\kanet\nine\src\（契約01〜03の成果）
- 地形: src/data/terrain-assets.ts の50cmハイトマップ（`getElevationAt(x,z)` あり）
- 建物: src/world/buildings.ts（フットプリント+実高さ。コライダー生成に再利用）
- ワールド準備完了イベントあり（E2: スポーンはロード完了後）

## 実装ガイド（設計は委ねるが、以下は決定事項）

- 物理: @dimforge/rapier3d-compat（WASM同梱系 — GitHub Pagesで追加ヘッダーなしで動くこと）
- 地形コライダー: ハイトフィールド（物理用は1024²以下に間引き可。描画地形との乖離が徒歩で気にならないこと）
- 建物コライダー: フットプリント押し出し（trimesh または convex分割。全建物一括のtrimeshチャンク化可）
- 徒歩: KinematicCharacterController。三人称カメラ（後方追従、マウス/スワイプで回転、建物へのカメラめり込み対策）。歩き/走り。**急坂対応必須**（この街は勾配20%超の坂が多い。autostepで縁石・段差を乗り越え）
- 車両: DynamicRayCastVehicleController。車の近くで乗車ボタン→運転、降車で徒歩へ（E2: 状態遷移でカメラ・入力・UIが正しく切り替わる）。車体はプロシージャル簡易モデルでよい（形状が破綻していなければ可）。坂道で滑り落ちないパーキングブレーキ
- スポーン: 住吉山手9-11付近の道路上。車両1台を近くに配置。**落下リスポーン**（y < 地形-20mで復帰）
- スマホ: 左バーチャルスティック（移動/ステア）+右画面スワイプ（視点）+乗降・アクセル・ブレーキボタン。タッチUIはタッチデバイス検出時のみ表示。pointer events で実装（マウスと共存）
- パフォーマンス: 物理は固定タイムステップ（60Hz）+補間。dtクランプ（タブ復帰時に爆発しない）
- 樹木・電柱等の小物コライダーは省略してよい（すり抜け許容。判断は委ねる）

## エッジケース

- E2: ロード完了前のスポーン禁止（物理初期化・コライダー生成完了後）。乗降遷移の入力・カメラ切り替え
- E3: dtクランプ、固定タイムステップ、タブ非アクティブからの復帰
- E17: 急坂（20%超）で徒歩が滑り落ちない・車が発進できる
- E18: 建物間の狭い路地・擁壁際でカメラが壁にめり込まない（近接時カメラ距離短縮）
- E19: 落下・エリア外 — リスポーンで復帰。見えない壁 or 引き返し警告はどちらでも可
- E20: モバイル判定 — タッチUIの出し分け。マウス+タッチ両方あるデバイス（Surface等）でも破綻しない
