# 契約02: 兵庫県50cm DSM/DEM 前処理パイプライン + 実高さ・高精細地形・樹木データの生成と注入

ダイヤル: Opus向けゴール委譲（内部設計は委ねる。E転写・合格基準・出力契約・エスカレーションは厳守）

## 目的

- 要求: 兵庫県50cmメッシュDSM/DEM（XYZテキスト図郭）から対象エリア2.4km四方の (a)建物ごとの実高さ (b)高精細地形ハイトマップ (c)樹木の位置・高さ を前処理で算出し、静的アセットとしてアプリに注入する。
- ゴール: 建物高さのヒューリスティックを実測値に置き換え、地形をDEM5A(5m)→50cm由来の高精細に引き上げ、実在の樹木配置を得る。ユーザー要望「可能な限り見た目を現実に近づける」の土台。
- 成功条件: ブラウザ表示で建物の高低差（マンションvs戸建て）が実際の街並みに一致し、地形が滑らかになり、樹木データが後続契約（植生描画）で使える形で出力される。

## 実装ガイド（設計は委ねるが、以下は決定事項）

- 前処理は Node スクリプト（例 `tools/build-terrain-assets.mjs`）。`npm run build:assets` で実行可能にする
- 手順の骨子:
  1. インデックスタイル（DSM/DEM、z16）をエリアbbox分取得 → `URL` 属性から必要図郭ZIPを列挙（重複除去）
  2. ZIPをダウンロード（1個約252MB。`.cache/` に保存し、再実行時はスキップ。curl等でリジューム可に）
  3. XYZテキストをストリーム解析し、エリアbbox内の点のみを 1mグリッドのDSM/DEMラスターに集約（平面直角V系→緯度経度→ローカルENUは data-spec.md の式と proj4 定義で）
  4. nDSM = DSM − DEM
  5. 建物実高さ: bvmap BldA フットプリント内の nDSM 上位パーセンタイル（p80〜p90目安、輪郭1m侵食）→ 高さ[m]。下限3m。出力は**クライアントと同一の決定的フットプリントハッシュ**をキーにしたマップ（契約01実装のハッシュ関数を共通化して使うこと）
  6. 高精細地形: DEMをエリア全域グリッド化（2048×2048目安）→ 量子化バイナリ or 16bit PNG で public/data/ に出力（gzip後数MB程度に収める）
  7. 樹木: nDSM≥3m かつ 建物フットプリント外 の領域から樹木点を抽出（局所極大やポアソンサンプリング等、方法は委ねる。位置x,z・高さ・冠幅目安を出力。エリア全体で数千〜数万点に間引き）
- クライアント側改修: 建物高さマップの適用（ハッシュ一致しない建物は従来ヒューリスティックにフォールバック）、高精細ハイトマップでの地形生成（欠損はDEM5Aフォールバック）、樹木データのロード口（描画は後続契約でよいが、単純なインスタンス円錐等の仮表示までやってよい）
- クレジットUI: data-spec.md §4.5 の兵庫県クレジット文言を追加（必須）
- 生成アセットは public/data/ に置き**コミット対象**（GitHub Pagesで配信するため）。合計50MB以下に収める（Pages/リポジトリ制約）

## エッジケース（転写 — 実装前に確認し、必要なら En+1.. を追補せよ）

- E1: 図郭境界・エリア端 — 複数ZIPにまたがる合成で継ぎ目に段差・欠損を作らない。エリア外周のデータ欠損は既存DEM5A値へフォールバック
- E3: 大容量処理 — 解析はストリームで（一括読み込みでOOMしない）。1コマンド10分制限があるためダウンロードと解析を分割実行できる構造に
- E5-a: 建物の浮き/埋まり — 高精細地形に切り替えた際、既存の建物基底ロジックが引き続き成立すること（目視確認対象）
- E10: 座標系変換ミス — 変換後のサンプル点が東灘区（lat 34.72-34.76, lon 135.24-135.28）に落ちることをスクリプト内でassert。DSM由来地表とGSI DEM5Aの中央値差3m以内を検証出力
- E11: nDSMの負値・ノイズ（DEM>DSMの箇所、水面、車・電線）— クランプと外れ値除去。建物高さの99%が[3m, 60m]に収まることを検証出力
- E12: ハッシュ不一致 — 前処理とクライアントで同一の正規化（座標量子化）をしないとキーがずれる。共通モジュール化し、一致率（高さが引けた建物の割合）を検証出力に含める（80%未満なら要調査として報告）
