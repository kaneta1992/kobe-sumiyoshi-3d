# 契約03: 近景品質ブラッシュアップ + AAA級ライティング（確定版）

ダイヤル: Opus向けゴール委譲

## 目的

- 要求: 徒歩視点（地上1.6m）で破綻しない近景品質と、AAAゲームを志向するライティングへ引き上げる。テクスチャの写実性よりライティング・形状・シルエットで見せる（ユーザー方針: 「最悪テクスチャはなくてもライティングでごまかせる」）。
- ゴール: 「実在の町を歩ける」体験の説得力。遠景は既に良好 — 近景のギャップを埋める。
- 成功条件: 地上視点のスクリーンショットで、箱の羅列ではなく「日本の住宅街」に見えること。60fps（デスクトップ）を維持。

## 実装ガイド（優先順。上から効果が大きい）

1. **屋根形状**: 普通建物(3101)に寄棟/切妻屋根（フットプリントOBBから生成、軒の出30-60cm）。屋根色は瓦グレー/ブラウン系を決定的ハッシュで
2. **植生（ユーザー明示要望: 高品質に作り込むこと — 本契約の最重要項目のひとつ）**:
   - 契約02の樹木点群（実在位置・実高さ）をインスタンス描画。LOD/カリングで数万本対応
   - 単一形状の複製にしない: 針葉樹/広葉樹/庭木など**複数樹種のバリエーション**（高さ・冠形から決定的に割り当て。六甲山麓は広葉樹二次林+スギ・ヒノキ、住宅地は庭木・街路樹）
   - 樹形はローポリでも多層カノピー（幹+枝ぶり+葉塊の重なり）でシルエットに凹凸を出す。ビルボード1枚板の見た目は不合格
   - 葉のシェーディング: 透過感（サブサーフェス風の裏面光）、法線を球状化して柔らかい陰影、風揺れ（階層的 — 幹はゆっくり・葉先は細かく）
   - **山肌の森**: 樹木点群が森として密な領域は、個別木+遠景は密度感のある表現（インポスター/クラスタ）で「緑の絨毯」にならないように
   - 低層植生: 生け垣・植込み・法面の下草を道路/建物際に決定的配置（住宅街の実在感）
3. **ライティング**: CSM（カスケードシャドウ）、GTAO/SSAO、bloom、ACESトーンマップ、物理的な空+太陽、ハイトフォグ（山の空気遠近感）。時刻はパラメータ化（デフォルトは昼下がり）
4. **ファサード**: 窓・階をプロシージャルシェーダーで（堅ろう建物=マンション風の連窓・バルコニー帯、戸建て=窓+玄関）。夜間窓明かりの仕込みは任意
5. **道路の質感**: アスファルトの色むら、白線（外側線・中央線は幅員に応じて）、歩道の縁石
6. **電柱・電線**: 道路沿いに決定的間隔で配置（日本の住宅街の実在感の要）。stretch: ガードレール、擁壁（急斜面の道路沿い）
7. **品質スケーラビリティ**: モバイル向けに解像度スケール・影/AO段階を用意（操作系タスクがスマホ対応のため）

## 追記（この追記が既存記述に優先する）— 2026-08-12 ユーザー要件追加: モバイル性能

- **性能目標: Google Pixel 7a（Android Chrome）で30fps以上、デスクトップで60fps** — ユーザー明示要件
- 計測基盤を実装すること: 画面内stats（fps / draw calls / triangles / GPUメモリ目安）。`?stats` で表示、常時計測は軽量に
- 品質プリセット: mobile / desktop の自動判定（UA・デバイスメモリ・実測fpsによる自動降格でも可）+ URLパラメータで強制切替。差分: 解像度スケール、影の解像度/カスケード数、AOの有無/簡略化、樹木の表示距離・インスタンス数・LOD段階
- カリングを構造に織り込む: 地形・建物・樹木・道路を**空間チャンク分割**してフラスタムカリング + 距離カリング。樹木は距離LOD（近: フルモデル / 中: 簡略 / 遠: インポスター or クラスタ）
- ドローコール予算: モバイル時 ≤100 / デスクトップ ≤300 目安（超える場合は理由と実測値を報告）
- 合格基準に追加: stats実測値（デスクトップfps・draw calls）を報告。Pixel 7a実機測定はメイン/ユーザーが実施（エージェントはモバイルプリセットでの動作確認まで）
