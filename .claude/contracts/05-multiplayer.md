# 契約05: P2Pマルチプレイ同期（WebRTC・サーバーレス）

ダイヤル: Opus向けゴール委譲

## 目的

- 要求: 複数人が同じ町を歩き・運転している姿を相互に見られるようにする（位置・向き・状態の同期）。
- ゴール: アプリの最終要件「マルチプレイで複数人で歩き回ったり車に乗れる」の実現。GitHub Pages（静的ホスティング）で動くこと＝サーバー実装なし。
- 成功条件: 2つのブラウザタブ/端末で同じURLを開くと、互いのアバター（徒歩/車両）がリアルタイムに滑らかに見え、片方を閉じると相手画面から消える。

## コンテキスト

- 既存実装: C:\Users\kanet\nine\src\（契約01〜04）。プレイヤー状態は src/game/ の `game.state`（mode/x,y,z/yaw/speed/vehicle{...}）から読める（契約04で外部読み取り用に公開済み — 形式はコードを読んで把握）
- アバター描画: src/game/avatar.ts（簡易人型・車の箱組み）を遠隔プレイヤー表示に再利用してよい
- ワールドは全クライアントで決定的（同一の建物・樹木）— 同期は動的な物のみでよい

## 実装ガイド（設計は委ねるが、以下は決定事項）

- ライブラリ: **trystero**（WebRTC P2P、公開シグナリング利用でサーバー不要。GitHub Pagesから動作すること）。ストラテジーは既定を第一候補に、接続不能時の代替ストラテジーへの切替は任意
- ルームID: `kobe-sumiyoshi-3d-v1`（`?room=` で上書き可能に）
- 送信: 自分の `game.state` を 10〜15Hz（変化がない時は間引き可）。座標はローカルENUのまま
- 受信: スナップショット補間（100〜200msバッファ）で滑らかに表示。ワープ・ガタつき不可（E3転写: P2P遅延100ms超でも破綻しない）
- 遠隔プレイヤー表示: 徒歩=人型アバター（色をピアIDから決定的に変える）、車両=車モデル。**遠隔の車・人にコライダーは付けない**（ゴースト。物理干渉なし — 位置の権威は各自）
- 車はプレイヤーごとに自分のワールドの車を運転する（1台の共有制御はしない。遠隔者が乗車中は遠隔側の車を状態から描画）
- UI: 接続人数の表示（HUD）。自分の名前入力等は不要（プロトタイプ）
- 性能: 遠隔アバターは軽量（フレームループ内アロケーションゼロの規律を維持）。想定同時数〜8人

## エッジケース

- E3: 補間・遅延・パケット順不同。タブ非アクティブからの復帰（自分の送信再開・相手の补間破綻なし）
- E26: ピアの参加/離脱 — 参加時スポーン表示、離脱・タイムアウト（5秒無受信）で除去
- E27: 不正値（NaN/エリア外座標）を受信しても自分の描画・物理が壊れない（クランプ/破棄）
- E28: シグナリング到達不能（企業ネットワーク等）— マルチプレイ無効のままシングルプレイとして動き続ける（エラーUIは控えめに）
- E29: 同一PCの2タブ（検証手段）で相互に見えること

## スコープと負の制約

- 変更してよい: src/**, index.html, package.json
- 変更禁止: orchestration-log.md, docs/**, .claude/**, .git/**, tools/**, public/data/**

- サーバーコード・外部サービスのAPIキーを必要とする構成は禁止
- Math.random() 禁止（ピア色などはピアIDハッシュで決定的に）
